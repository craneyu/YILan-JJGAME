# scripts/

## e2e-scoring.sh — 評分到匯出的端對端測試

從零建立一個同時含傳統演武與創意演武的賽事，**所有分數都透過真實 API 產生**
（不直接寫入資料庫），再驗算排名結果與權限。

```bash
./scripts/e2e-scoring.sh
```

退出碼 0 代表全部通過；非 0 時每個失敗項目會印一行 `FAIL`。

### 涵蓋範圍

| 項目 | 內容 |
| --- | --- |
| 傳統演武 | 開放動作、5 位裁判評分、VR 多樣性、錯誤攻擊、棄權、換組、完全未評分的隊伍 |
| 創意演武 | 開放評分、計時起停、違例扣分（技術／表演兩邊）、5 位裁判評分 |
| 排名 | 扣分歸屬、平分以技術分決勝、未評分與棄權的排除 |
| 權限 | `judgeDetails` / `judgeScores` 僅 admin 可見，排名本身維持公開 |

不涵蓋瀏覽器 UI（觀眾端畫面、匯出按鈕點擊）。匯出表的內容由排名 API 的資料算出，
因此資料正確即涵蓋大部分匯出邏輯；UI 需要另行手動確認。

### 前置需求

- 執行中的 MongoDB 容器（預設 `jju-mongo`，可用環境變數 `MONGO_CONTAINER` 覆寫）
- port 3001 未被佔用
- `backend/` 已 `npm install`

### 安全邊界

- 只使用專用測試資料庫 `jju_e2e`，**不會碰到正式的 `jju`**；腳本內有名稱防呆
- 測試後端跑在 port 3001，不影響開發用的 3000
- 無論成功失敗或中途中斷，結束時都會停掉測試後端並刪除測試資料庫

### 改期望值時

`e2e-assert.py` 的期望值是依 `e2e-scoring.sh` 送出的評分手算而來，**兩者必須一起改**。
計分規則本身變更時（例如扣分歸屬、平手判定），改完程式碼要同步更新這兩個檔案，
讓這支腳本持續反映當前規則。
